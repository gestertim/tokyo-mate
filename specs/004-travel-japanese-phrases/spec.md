# Feature Specification: Tokyo Mate 東京通｜旅遊日文 Travel Japanese

**Feature Branch**: `004-travel-japanese-phrases`

**Created**: 2026-09-21

**Status**: Draft

**Input**: User description: "繁體中文旅客在東京旅行時，常知道自己想說什麼，卻不知道如何用自然、簡單、禮貌的日文表達。Feature 004 解決『我知道自己想說什麼，但不知道日文怎麼說』的問題：旅行情境 → 快速找到一句 → 看繁體中文確認意思 → 顯示日文 → 必要時播放日文給對方聽。正式功能涵蓋 7 個旅行情境分類、日文句子卡（日文＋繁中翻譯＋語音播放）、日文語音播放（含播放狀態與單一 active playback）、快速搜尋（繁中／日文、部分關鍵字、僅回傳正式 dataset）、收藏常用句（跨分類收藏狀態一致，不需帳號／Cloud／多裝置同步）。正式 dataset 需 7 類、每類至少 20 個高實用性 category placements、總計至少 140 個 category placements，並涵蓋 safety-critical 求助／緊急句子。"

## Clarifications

### Session 2026-09-21

- Q: 為避免用少量 phrase 大量跨情境重複來「湊」出至少 140 個 category placements，是否需要在 Specification 中訂出最低 unique phrase 數量門檻？ → A: 新增獨立的 unique phrase 最低數量門檻（不限制單一 phrase 可跨幾個情境），正式 dataset 的 unique phrase 總數 MUST 至少為 100；重複性與實用性仍交由既有審查機制（FR-029）把關。
- Q: 「求助／緊急狀況」情境中的醫療／過敏／緊急句子，除了 FR-028 的呈現方式限制外，是否需要新增 MUST 顯示明確可見的安全提醒／免責文字？ → A: 是，「求助／緊急狀況」情境 MUST 顯示明確可見的安全提醒文字（例如提醒使用者翻譯僅供參考、緊急狀況仍須尋求正式協助），不得僅以未言明的隱含方式呈現。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 依旅行情境找到並理解合適的日文句子 (Priority: P1)

正在東京旅行或準備前往東京旅行的繁體中文旅客，不需具備日語讀寫能力，依照自己所在的旅行情境（機場、飯店、餐廳點餐、購物、交通、求助／緊急狀況、日常溝通）瀏覽日文句子，先以繁體中文確認句子的意思，再取得對應的日文文字，必要時可把手機畫面直接給日本人看。

**Why this priority**: 這是 Feature 004 存在的第一個核心理由——先讓使用者能找到並看懂一句符合情境、可直接使用的日文，若此能力不存在，其餘功能（搜尋、播放、收藏）都沒有可依附的內容。

**Independent Test**: 測試者進入「旅遊日文」，選擇任一旅行情境，瀏覽該情境下的句子卡，確認每張句子卡同時顯示日文與自然的繁體中文翻譯，即可獨立驗證此價值，不需要先完成搜尋或收藏。

**Acceptance Scenarios**:

1. **Given** 使用者進入「旅遊日文」，**When** 使用者查看情境清單，**Then** 可看到 7 個正式旅行情境（機場、飯店、餐廳點餐、購物、交通、求助／緊急狀況、日常溝通）。
2. **Given** 使用者選擇任一情境，**When** 使用者瀏覽該情境下的句子，**Then** 該情境至少提供 20 個高實用性 category placements。
3. **Given** 使用者查看任一正式句子卡，**When** 句子卡顯示，**Then** 同時包含日文文字、自然的繁體中文翻譯，以及可播放日文語音的操作。
4. **Given** 使用者只看得懂繁體中文，**When** 使用者閱讀句子卡，**Then** 可先透過繁中確認句子意思，再取得可直接展示給日本人看的日文文字。
5. **Given** 同一句話合理適用於多個情境，**When** 使用者在不同情境中看到它，**Then** 該句子的日文、繁中翻譯與語音能力保持一致，不因分類不同而出現內容不一致的重複版本。

---

### User Story 2 - 播放日文語音給對方聽 (Priority: P1)

使用者在對方看不懂繁中、自己也不會唸日文的情況下，需要讓手機直接播放正式句子的日文語音給日本人聽，並清楚知道語音目前的播放狀態。

**Why this priority**: 「顯示日文」不足以涵蓋所有溝通情境；許多情況下使用者需要對方用「聽」的方式理解，語音播放是核心體驗中不可或缺的最後一步。

**Independent Test**: 測試者對任一正式句子卡觸發語音播放，可獨立觀察到播放已被要求、播放中、以及播放失敗（若模擬失敗情境）等狀態，並確認同一時間只有一個句子處於播放中，不需要先完成搜尋或收藏流程。

**Acceptance Scenarios**:

1. **Given** 使用者對某句子觸發播放，**When** 播放被要求後尚未開始，**Then** 使用者可理解「已要求播放」的狀態。
2. **Given** 語音正在播放，**When** 使用者查看該句子卡，**Then** 使用者可理解「播放中」的狀態。
3. **Given** 語音播放發生錯誤，**When** 播放失敗，**Then** 使用者可理解「播放失敗」的狀態，且該句子的文字、繁中翻譯仍然可讀。
4. **Given** 句子 A 正在播放，**When** 使用者觸發句子 B 的播放，**Then** 句子 B 的播放取代句子 A，同一時間最多只有一個句子處於 active playback。
5. **Given** 任一單一句子的語音播放失敗，**When** 使用者繼續使用其他功能，**Then** 文字顯示、搜尋、分類瀏覽、收藏與其他句子的播放皆不受影響。

### User Story 3 - 快速搜尋日文或繁中關鍵字找到句子 (Priority: P2)

使用者記得部分想表達的中文或看到的日文片段，但不想逐一瀏覽情境分類，透過搜尋直接找到符合的正式句子。

**Why this priority**: 情境瀏覽適合「還不確定想找什麼」，搜尋則服務「已經有明確關鍵字」的旅客；沒有搜尋，使用者在句子量增加後仍須依賴分類逐一尋找。

**Independent Test**: 測試者輸入部分繁中或日文關鍵字，可獨立確認搜尋結果僅來自正式 dataset、可直接播放與收藏，不需要先完成分類瀏覽或收藏流程。

**Acceptance Scenarios**:

1. **Given** 使用者輸入部分繁體中文關鍵字，**When** 該關鍵字符合正式 dataset 中的內容，**Then** 對應的正式句子出現在搜尋結果中。
2. **Given** 使用者輸入部分日文關鍵字，**When** 該關鍵字符合正式 dataset 中的內容，**Then** 對應的正式句子出現在搜尋結果中。
3. **Given** 使用者查看搜尋結果，**When** 結果顯示，**Then** 每筆結果皆來自正式 dataset，不即時產生 dataset 之外的新翻譯或新句子。
4. **Given** 使用者查看任一搜尋結果，**When** 使用者與該結果互動，**Then** 可直接查看日文、查看繁中、播放語音與收藏，不需要進入額外的句子詳細頁面。
5. **Given** 使用者輸入的關鍵字沒有符合的正式句子，**When** 搜尋沒有結果，**Then** 顯示可理解的空白狀態，且不產生任何虛構的句子。

---

### User Story 4 - 收藏常用句以便重複使用 (Priority: P2)

使用者旅行途中重複用到某些句子（例如常點的餐點、常問的問題），希望收藏這些句子，之後可以直接從「我的常用句」找到，不用重新瀏覽分類或重新搜尋。

**Why this priority**: 收藏讓「快速找到一句」的核心體驗延伸到重複使用場景，是搜尋與情境瀏覽之外，第三種找到句子的方式，能降低重複行程中的操作成本。

**Independent Test**: 測試者對任一正式句子收藏，之後從「我的常用句」瀏覽確認該句子出現，並確認同一句子無論從哪個情境或搜尋結果收藏，收藏狀態一致，不需要先完成其他使用者故事的流程。

**Acceptance Scenarios**:

1. **Given** 使用者查看任一正式句子，**When** 使用者收藏該句子，**Then** 該句子被加入「我的常用句」。
2. **Given** 使用者已收藏的句子，**When** 使用者取消收藏，**Then** 該句子從「我的常用句」移除。
3. **Given** 使用者已收藏一或多句，**When** 使用者進入「我的常用句」，**Then** 可瀏覽所有已收藏的正式句子。
4. **Given** 同一句子出現在多個情境分類中，**When** 使用者在任一情境或搜尋結果中收藏該句子，**Then** 該句子在其他情境或搜尋結果中的收藏狀態同步呈現為已收藏，不會出現分類各自獨立的收藏副本。
5. **Given** 使用者尚未收藏任何句子，**When** 使用者進入「我的常用句」，**Then** 顯示可理解的空白狀態，並提供回到情境瀏覽或搜尋的方式，而非無說明的空白畫面。

---

### User Story 5 - 在求助／緊急狀況中快速辨識並取得安全相關句子 (Priority: P2)

使用者在身體不適、需要警察或救護車協助、遺失重要物品，或需要對方停止某個動作等緊急情況下，需要在「求助／緊急狀況」情境中快速辨識並取得這些高重要性句子，不被其他一般日常句子淹沒。

**Why this priority**: 緊急狀況下的可用性直接關係到使用者的人身安全與求助效率；若 safety-critical 句子與一般句子混雜、難以辨識，情境分類的價值在最需要的時刻反而失效。

**Independent Test**: 測試者進入「求助／緊急狀況」情境，可獨立確認警察協助、救護車、要求對方停止、身體不舒服、遺失重要物品、找醫院／警察／藥局等句子具有較高資訊優先級與容易辨識的呈現方式，不依賴顏色作為唯一辨識依據。

**Acceptance Scenarios**:

1. **Given** 使用者進入「求助／緊急狀況」情境，**When** 使用者瀏覽該情境下的句子，**Then** 至少涵蓋警察協助、救護車、要求對方停止、身體不舒服、遺失重要物品、找醫院／警察／藥局等 safety-critical 句子。
2. **Given** 該情境同時包含 safety-critical 與一般日常句子，**When** 使用者瀏覽，**Then** safety-critical 句子具有較高資訊優先級與容易辨識的呈現方式，不被一般內容淹沒。
3. **Given** 使用者僅能辨識顏色以外的視覺線索（例如色盲或黑白顯示情境），**When** 使用者瀏覽該情境，**Then** 仍可辨識出 safety-critical 句子，不依賴顏色作為唯一辨識方式。
4. **Given** 使用者查看醫療、過敏或緊急相關句子（例如表達「我有過敏」），**When** 使用者使用該句子與對方溝通，**Then** 產品呈現方式不得暗示翻譯必然準確、已完成醫療診斷、緊急服務必定成功、食品安全已獲確認，或對方必定理解與接受使用者的要求。

---

### Edge Cases

- 語音播放失敗時：句子文字、繁中翻譯、搜尋、分類瀏覽、收藏，以及其他句子的播放皆維持可用，不因單一語音失敗而整體不可用。
- 搜尋沒有符合的正式句子時：顯示可理解的空白狀態，不生成 dataset 之外的假句子。
- 「我的常用句」尚未收藏任何句子時：顯示可理解的空白狀態，並提供回到情境瀏覽或搜尋的路徑。
- 正式資料異常導致某情境無法顯示應有的內容（正常情況下每類至少 20 個 category placements）時：顯示可理解的狀態、保留離開該畫面的方法，不造成整個 App 失效。
- 使用者在句子播放中途離開該句子卡或切換情境時：系統不得讓已中止的播放繼續佔用 active playback 狀態。

## Requirements *(mandatory)*

### Functional Requirements

**情境分類與句子內容**

- **FR-001**: 系統 MUST 提供 7 個正式旅行情境：機場、飯店、餐廳點餐、購物、交通、求助／緊急狀況、日常溝通。
- **FR-002**: 每個正式旅行情境 MUST 至少提供 20 個高實用性 category placements。
- **FR-003**: 全部正式 category placements 總數 MUST 至少為 140。
- **FR-004**: 系統 MUST 能分別統計 unique phrase 數量與 category placement 數量，兩者不得混淆；此統計供
  dataset validation、內容審查與 acceptance verification 使用，Feature 004 MVP 不要求在旅客可見的使用者
  介面中顯示這些統計數字。
- **FR-005**: 同一句合理適用於多個情境時，系統 MUST 以同一 unique phrase 呈現在各情境中，不得以複製相同 phrase 內容的方式灌注 category placement 數量。
- **FR-006**: 每個正式句子 MUST 至少包含日文文字、自然的繁體中文翻譯、日文語音播放能力，以及所屬的一個或多個旅行情境。
- **FR-007**: 每個正式句子的日文文字 MUST 適合使用者在必要時直接把手機畫面展示給日本人看。

**語音播放**

- **FR-008**: 每個正式句子 MUST 具備日文語音播放能力。
- **FR-009**: 使用者 MUST 能理解句子目前處於「已要求播放」「播放中」或「播放失敗」其中一種狀態。
- **FR-010**: 系統 MUST 確保同一時間最多只有一個句子處於 active playback。
- **FR-011**: 當使用者於另一句子仍在播放時觸發新的播放，系統 MUST 以新的播放取代原本的 active playback。
- **FR-012**: 任一單一句子的語音播放失敗，MUST NOT 導致文字顯示、搜尋、分類瀏覽、收藏功能或其他句子的播放無法使用。

**搜尋**

- **FR-013**: 系統 MUST 支援以繁體中文關鍵字搜尋正式句子。
- **FR-014**: 系統 MUST 支援以日文關鍵字搜尋正式句子。
- **FR-015**: 系統 MUST 支援部分關鍵字（不需完整句子）進行搜尋並找到符合的正式句子。
- **FR-016**: 搜尋結果 MUST 只來自正式 dataset，MUST NOT 即時生成 dataset 之外的新句子或新翻譯。
- **FR-017**: 使用者 MUST 能直接在搜尋結果中查看日文、查看繁中翻譯、播放語音與收藏，不需要進入額外的句子詳細頁面。
- **FR-018**: 當搜尋沒有符合的正式句子時，系統 MUST 顯示可理解的空白狀態，MUST NOT 產生虛構的句子。

**收藏常用句**

- **FR-019**: 使用者 MUST 能收藏任一正式句子。
- **FR-020**: 使用者 MUST 能取消收藏已收藏的句子。
- **FR-021**: 使用者 MUST 能從「我的常用句」瀏覽所有已收藏的正式句子。
- **FR-022**: 同一 unique phrase 無論出現在哪個情境或搜尋結果中，MUST 呈現一致的收藏狀態；收藏或取消收藏一次即套用至該句子在所有情境與搜尋結果中的呈現。
- **FR-023**: 使用者收藏的句子 MUST 在同一裝置上重新開啟 App 後仍然存在（是否使用帳號、雲端或裝置本機方式保存為 Technical Plan 決定事項，本規格不預先指定）。
- **FR-024**: 「我的常用句」尚未收藏任何句子時，系統 MUST 顯示可理解的空白狀態，並 MUST 提供回到情境瀏覽或搜尋的方式。

**求助／緊急狀況與安全溝通**

- **FR-025**: 「求助／緊急狀況」情境 MUST 至少涵蓋：請求警察協助、請求救護車、要求對方停止、表達身體不舒服、遺失重要物品、尋找醫院／警察／藥局等 safety-critical 句子。
- **FR-026**: Safety-critical 句子 MUST 具有較高的資訊優先級與容易辨識的呈現方式，MUST NOT 被該情境中的一般內容淹沒。
- **FR-027**: 系統 MUST NOT 以顏色作為辨識 safety-critical 句子的唯一方式。
- **FR-028**: 涉及醫療、過敏或緊急狀況的句子，其呈現方式 MUST NOT 暗示翻譯必然準確、已完成醫療診斷、緊急服務必定成功、食品安全已獲確認，或對方必定理解並接受使用者的請求。

**資料品質**

- **FR-029**: 正式 dataset 納入產品前 MUST 檢查日文自然度、禮貌程度、是否適合旅客直接使用、繁中翻譯自然度、實際旅行價值、是否有不必要重複、multi-category 適用性，以及醫療／過敏／緊急用語的安全性。
- **FR-030**: 系統 MUST NOT 為了湊滿每類至少 20 個 category placements 而保留經審查為低價值的句子。

**Regression 與範圍邊界**

- **FR-031**: Feature 004 MUST NOT 破壞既有 Feature 001（Tokyo Travel Assistant）、Feature 002（Photo Translate）與 Feature 003（Nearby Map & Navigation）既有的可觀察行為、既有 API endpoints、既有 PWA behavior 與既有自動化測試。
- **FR-032**: Feature 004 MUST NOT 要求使用者帳號、Cloud Database、Cloud 收藏同步或多裝置同步。
- **FR-033**: Feature 004 MUST NOT 提供即時 AI 生成的旅遊日文句子、自由對話或聊天機器人；所有句子皆來自正式審查過的 dataset。

**資料多樣性**

- **FR-034**: 正式 dataset 的 unique phrase 總數 MUST 至少為 100，作為獨立於 category placement 總數之外的多樣性門檻，避免以少量 phrase 大量跨情境重複來達成 FR-003 的 placement 數量要求；本要求不限制單一 phrase 可跨幾個情境，重複性與實用性仍依 FR-029 審查機制把關。

**求助／緊急狀況安全提醒**

- **FR-035**: 「求助／緊急狀況」情境 MUST 顯示明確可見的安全提醒文字（例如提醒使用者翻譯僅供參考、緊急狀況仍須尋求正式協助），不得僅依賴 FR-028 對呈現方式的限制而省略明確可見的提醒。

### Key Entities *(include if feature involves data)*

- **Phrase（句子）**：一個 unique 的旅遊日文表達內容，包含日文文字、自然的繁體中文翻譯、日文語音播放能力，以及是否為 safety-critical 的辨識資訊。同一 Phrase 可關聯至一個或多個 Category。
- **Category（旅行情境）**：7 個正式旅行情境之一（機場、飯店、餐廳點餐、購物、交通、求助／緊急狀況、日常溝通），作為使用者瀏覽 Phrase 的入口。
- **Category Placement（情境內容配置）**：一個 Phrase 出現在一個 Category 中的關聯關係；同一 Phrase 出現在多個 Category 時，形成多個 Category Placement，但仍指向同一個 Phrase，不視為內容重複。
- **Favorite（收藏）**：使用者在裝置上對某個 unique Phrase 標記為常用句的狀態；同一 Phrase 的收藏狀態跨所有 Category 與搜尋結果一致。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者從進入「旅遊日文」到看到一句符合所選旅行情境、同時包含日文與繁中翻譯的句子，可在 10 秒內完成。
- **SC-002**: 100% 的正式句子同時具備日文文字、自然繁中翻譯與可用的語音播放操作。
- **SC-003**: 7 個正式旅行情境中，每一個都至少提供 20 個高實用性 category placements，且全部情境的 category placements 總數至少 140。
- **SC-004**: 使用者輸入與正式 dataset 相符的部分繁中或日文關鍵字進行搜尋時，能在搜尋結果中找到對應的正式句子。
- **SC-005**: 任一句子語音播放失敗時，100% 的情況下文字顯示、搜尋、分類瀏覽與收藏功能仍可正常使用。
- **SC-006**: 使用者進入「求助／緊急狀況」情境後，可在 5 秒內辨識出至少一個 safety-critical 句子，不需先瀏覽完整清單。
- **SC-007**: 使用者對同一句子在任一情境或搜尋結果中收藏後，於其他出現該句子的情境或搜尋結果中查看，100% 呈現一致的收藏狀態。
- **SC-008**: Feature 001、002、003 既有的自動化測試在 Feature 004 上線後維持 100% 原有通過狀態，不因本功能新增而回歸失敗。
- **SC-009**: 90% 以上的使用者在首次使用「旅遊日文」時，能透過情境瀏覽或搜尋，成功找到並顯示自己需要的句子，無需額外說明或協助。
- **SC-010**: 正式 dataset 上線時，unique phrase 總數至少為 100。
- **SC-011**: 使用者進入「求助／緊急狀況」情境時，100% 可看到明確可見的安全提醒文字，不需額外操作即可察覺。

## Assumptions

- 語音播放採用的技術方案（例如瀏覽器內建語音能力或其他方案）留待 Technical Plan 決定，本規格僅定義可觀察的播放狀態與行為。
- 收藏資料的實際保存方式（例如裝置本機儲存或其他機制）留待 Technical Plan 決定，本規格僅要求收藏狀態在同一裝置上於 App 重新開啟後仍然存在，且不要求帳號、Cloud Database 或多裝置同步。
- 正式 dataset 的最終句子內容（涵蓋 7 類、每類至少 20 個 category placements、總計至少 140 個）將於後續內容製作與審查階段完成，並依本規格列出的日文自然度、禮貌程度、翻譯品質、重複性、實用性與安全用語標準把關；本規格不預先鎖定每一句最終文字。
- 「旅遊日文」作為既有 App 內的新功能項目，其在既有導覽結構中的確切進入點與呈現方式留待 UX/Plan 階段決定，本規格僅定義使用者可以進入並使用此功能。
- 使用者介面語言維持與既有 App 一致的繁體中文，不在本功能中新增語言切換需求。
- 使用者於旅行途中使用行動裝置操作本功能，沿用既有 App 對網路連線與裝置環境的既有假設，不在本規格中另行定義新的離線或效能需求。
