## 2026-10-07 Epoch 操作語意與候選 UX（本輪現行）

已批准：正常signing key輪替不等於舊有效capability不能首次執行；本人Session／資格／限流／成本／epoch authority／原子首次grant全部成立且尚未grant時，仍可首次執行一次。已grant則相同內容duplicate／不同內容conflict，不因fingerprint輪替變成新操作。洩漏撤銷／退役擋新grant，不取消既有入帳或uncertain占用；settled仍非內容成功。產品無需僅因正常輪替新增錯誤提示。

不在登入／focus／網路恢復／正常輪替／到期自動簽發、補送或換handle；token／命令僅當頁記憶體，不進URL、持久storage或PWA cache。上述UI已完成本機實作／隔離驗證：unknown→原命令確認仍零付費POST→再次明確送出；唯讀lookup與reload均不重送。管理者本機頁預設dry-run，第一步檢視後才可第二步確認；unknown重試保持同operation ID及該步冪等識別。正式cutover／服務及production UX仍未驗。

## 管理者儀表板（新增，獨立於一般使用者介面）

範圍限定：僅管理付費 API 使用資格、等級、額度追加與必要稽核；不擴充為完整會員管理、行銷或通知系統。每個頁面對應的資料讀取與異動 API 均需後端逐請求驗證管理者權限（對應 FR-032）。

### 1. 總覽頁

- 核准狀態統計（待審核、已核准、已撤銷、已拒絕人數）。
- 日／週估算用量彙總（全站級別彙總，不顯示供應商實際帳單）。
- 接近日／週上限之使用者提示清單（80%僅示例，非正式核准值）。門檻由可信後端明列注入，未核定不自行設預設；前端不自行判定或用於付費授權。
- 必要防護服務狀態（身分驗證、額度查詢、原子預留）目前是否可用；服務異常時顯示非金額性警示，不自行推演具體原因。

### 2. 使用者清單與詳情

- 清單顯示每位使用者之最少必要識別資訊（例如顯示名稱或部分遮蔽之聯絡方式）、目前核准等級、日／週額度狀態摘要。
- 詳情頁顯示日／週已使用、預留中、剩餘估算額度、下一次重置時間，以及六端點各自的用量摘要（次數與估算成本，非完整請求內容）。
- 禁止顯示：完整對話內容、音檔、影像、token、密鑰，以及完整邀請名單匯出。

### 3. 待審核事項

- 列出兩類待審核項目：新使用者付費資格申請、週額度用盡後的追加額度申請。
- 每項顯示判斷所需之最少必要資訊（例如申請時間、目前等級、週額度用盡狀況）。

### 4. 操作與稽核

- 支援核准、拒絕、切換等級、撤銷、追加額度五類操作。
- 追加額度表單必須要求明確輸入金額（正值）、適用範圍與有效期限，並標示只對指定使用者及該週有效（不得跨週）；日上限仍獨立有效。2026-09-25 已由營運者核准：**單次金額、同週次數與累計金額均無固定上限**，管理者逐次自行決定；UI 不得假設任何具體上限數字，但也不得提供「永久」或「跨週」選項（有效期限仍限於該週）；表單建議顯示「本次追加後之週累計金額」供管理者參考。
- 重要異動（撤銷、降級、追加）必須先顯示明確確認步驟（例如二次確認對話框），但確認步驟只是 UX 防誤操作設計，不取代後端逐請求授權檢查，也不能作為唯一防 CSRF 或防重複提交手段。
- 每次操作完成後顯示成功或失敗狀態，並更新清單／詳情顯示。
- 固定顯示：此頁所見為估算成本與內部額度控制，非供應商實際帳單；管理者自身也受同一套額度與原子預留約束，追加額度為唯一例外路徑，其金額與次數由管理者逐次決定且無固定上限；頁面需同時如實揭露「沒有週追加累計上限，無法僅靠個人週額度保證整站帳單上限」。

## 使用者流程

### Public 或未核准

1. 使用者可瀏覽公開內容與進入既有功能畫面。
2. 當明確操作需要付費 API 時，UI 在觸發區塊顯示對應資格提示；後端仍是唯一權威，必須在上游前拒絕。
3. 未登入的主要操作為「登入」；已登入但未核准的主要操作為「查看公開內容」或「登出」。
4. 已拒絕的操作不自動轉成登入後、核准後或網路恢復後重送。
5. 探索附近的地圖位置顯示靜態示意圖與「查看東京百科」操作；重新整理、舊分頁恢復、模式或資格變更後仍須先依最新狀態決定是否可掛載互動地圖，不得沿用舊元件觸發圖磚或搜尋。

### 有效核准、撤銷與等級變更

- 有效核准者依現有功能位置手動送出付費請求；不需要新增全站會員頁。
- 付費功能入口顯示核准等級，以及日／週「已使用」「預留中」「剩餘估算額度」「重置時間」。此顯示來自可信後端，只供使用者參考；是否放行仍由每次付費 API 請求前的後端原子預留決定。
- 若額度查詢失敗、資料過期或分頁閒置過久，入口顯示「目前無法確認額度狀態」等非金額狀態，不顯示舊剩餘金額，也不得把 stale 畫面當作可用保證。
- 完成一次請求後，UI 必須以後端最新結算狀態更新已使用、預留中與剩餘估算額度；成功、明確未計費失敗、逾時與不確定是否計費都依後端規則呈現，不自行推算。
- 後端 403 時，立即以最新狀態更新原功能區塊：「此帳號目前沒有有效的付費功能核准資格。你仍可查看公開內容。」
- 管理者撤銷、拒絕、核准到期或變更等級後，下一次付費操作適用新結果。UI 不承諾顯示管理者內部原因或稽核資料。
- 有效核准者只有在日／週額度均可用時才顯示既有互動地圖；日或週額度暫不可用、資格撤銷或到期時，地圖位置切換為靜態示意圖。切換不得只用 CSS 隱藏已初始化的地圖，且不得自動補送先前搜尋。

## 靜態東京風格示意圖（方案 A）

### 呈現與裁切

- 靜態圖為東京街區風格的視覺示意，不是真實地圖、即時地理資料或目前位置。聊天附圖只作視覺參考；本機 repository 未提供可據此假定存在的圖片檔，正式資產的取得、授權、最佳化與整合方式留待後續已批准 Plan／Implement。
- 手機寬度小於 768px 時，圖片框採 `4:3`，以視覺主體中心裁切；桌面寬度 768px 以上時採 `16:9`，同樣以中心為裁切焦點。正式資產須在兩種裁切下保留主要東京街景辨識元素，重要資訊不得只存在於可能被裁掉的邊緣。
- 圖片框上方或緊鄰位置固定顯示繁體中文標示「示意圖」；標示為介面文字，不依賴圖片內嵌文字，且不可因裁切消失。
- 圖片替代文字固定表達：「東京街區風格示意圖，非即時地圖或真實地理資料。」裝飾性細節不另作冗長描述。

### 能力邊界與操作

- 靜態示意圖不得顯示或暗示即時位置、使用者定位、搜尋結果 marker、可點選地點、pan、zoom、路線或導航能力；圖片本身不可作為互動控制。
- 圖片下方提供「查看東京百科」操作，前往既有公開內容；不得以此操作觸發 `/api/places`、Geoapify 或其他付費外部服務。
- 圖片載入失敗時，保留相同版面區域並顯示可讀文字：「地圖示意圖目前無法顯示，你仍可查看東京百科。」同時保留「查看東京百科」操作；不得留下空白框、破圖圖示或把失敗誤寫成定位錯誤。
- 受限狀態的畫面不可掛載 `NearbyMap` 或任何會呼叫圖磚代理的元件。CSS `display: none`、透明度、遮罩或移出畫面均不能作為停止圖磚請求的設計或驗收方式。有效核准者的互動地圖圖磚一律經後端 `/api/map/tile/*` 代理逐請求驗證，前端不得保留可繞過代理的直連路徑。

### 狀態切換

**本輪 P-G1／P-G2 同步（2026-10-06）**：G-B 與 A6 六列不變，沒有新文案、額度、縮圖或錄音決策。所有可變成本請求即使 R_e 較低，當日／週 `remaining < G` 仍全域不可用；G／資格與額度由同次後端原子結果決定，不由 UI 快照或 frontend 重算。registry 更新／封鎖使後續新請求重新判斷，已成立 grant 不追溯作廢；不自動重送舊操作。每筆 tile 仍由代理重新驗證，不能把 eligibility 查詢當成 grant。此為文件同步，UI／handler 尚未接線，七檔結案不重審；連續實作邊界見 [Readiness](checklists/pipeline-readiness-report.md)。

- Public、未登入、未核准、已撤銷、已到期、日／週實際耗盡與 `below_floor` 全域不可用狀態，一律採靜態示意圖（見 plan.md §4.5；`below_floor` 不稱「額度已滿」，單一 request 預留不足不屬此類）。
- 窗口重置、管理者核准或追加額度後，不自動恢復舊搜尋；UI 取得最新可信狀態後才可呈現互動地圖，Places 搜尋仍須由使用者重新明確操作。
- 核准資格撤銷、到期或額度耗盡時，已開啟畫面須在最新狀態生效後卸除互動地圖能力並切換為靜態示意圖；舊分頁不可保留可繼續請求圖磚或搜尋的能力。

### 額度呈現規則

- 金額使用美元 `US$`，顯示到小數點後兩位；必要時可搭配「估算」字樣，但不得稱為「實際帳單」或「保證不超支」。
- 日／週重置時間由可信後端提供；權威時區為 `Asia/Taipei`，日窗口於每日 00:00、週窗口於每週一 00:00 重置。UI 不使用瀏覽器時鐘自行判定恢復，並需能呈現後端提供的下一次重置時間；跨日、跨週、跨時區操作與夏令時間變化不得提前或延後恢復。
- 「預留中」必須與「已使用」分開顯示，避免使用者誤以為在途請求已完全結算。
- 額度狀態不得公開邀請名單、其他使用者額度或可識別個人的同級用量資訊。
- 舊分頁、重新整理、重複提交或直接呼叫 API 都不能依前端顯示放行；UI 文案不得暗示畫面上的剩餘額度具有授權效力。
- 若端點成本上界無法在呼叫前由可信後端 registry 與估算器界定，UX 必須顯示上述統一 503 狀態，不揭露價表版本／內部原因，也不得將金額或版本選擇權交給使用者。能由合法輸入縮限解決的情況，才可提示縮短文字、縮小影像或其他計費參數。
- **輸入限制的使用者可見行為（2026-10-06 提案，待營運者核准；plan.md §4.2、§10.3.2 A3／A4）**：語音輸入單次最長 60 秒，錄音達 60 秒時自動停止並提示「已達單次錄音上限，請分段錄音」，不得靜默截斷；照片送出前由前端縮至供應商可處理的尺寸（不改變選取範圍），超過大小上限時顯示可操作提示「請縮小選取範圍或重新選擇照片」；文字／發音輸入超過既有字數上限時沿用既有提示，並顯示剩餘字數。以上限制是額度防護的輸入邊界，不是產品功能縮減，文案不得暗示「額度不足」。**A10＝P1 規劃已核准的使用者可見後果（文案待 UX 確認）**：錄音格式改為固定格式 PCM WAV（使用者無感）；若瀏覽器無法產生該格式（可行性待真實瀏覽器驗證），須明確提示改用文字輸入，不得靜默失敗或改送其他格式。
- **額度與防護狀態必須分開呈現**：端點請求不足只影響該請求；全域額度耗盡與 `remaining < G` 依各自的 429 語意呈現；成本模型失效、過期、未證明或封鎖一律使用統一 503，不顯示額度／價表資訊，地圖位置顯示靜態示意圖。production 六端點維持 `live: false`，直至可信 registry 的證據、有效期、核准及實際啟用條件全部成立。

### 日與週額度

| 狀態 | HTTP | 繁體中文文案 | 主要操作 | 恢復行為 |
| --- | --- | --- | --- | --- |
| 未登入或 Session 無效 | 401 | 需要登入才能使用這項付費功能。 | 登入 | 登入且另有有效核准後，使用者重新操作 |
| 已登入但資格未核准、撤銷或到期 | 403 | 此帳號目前沒有有效的付費功能核准資格。你仍可查看公開內容。 | 查看公開內容／登出 | 管理者有效核准後，使用者重新操作 |
| 日／週實際耗盡（`quotaScope: 'all'`） | 429 | 逐字採下方 A6 日／週耗盡列，不合併文案 | 查看公開內容；週耗盡可聯絡管理者 | 日待新日窗口；週待有效追加或新週窗口，日上限仍獨立有效；重新確認後手動重試 |
| 日／週 below_floor（`quotaScope: 'all'`） | 429 | 逐字採下方 A6 below_floor 日／週列，不稱已滿 | 查看公開內容／稍後確認額度 | 可信結算／釋放預留、重置或有效週追加可能恢復；uncertain 不自動釋額；週追加不提高日上限，也不保證恢復 |
| 日／週本次 request 不足（`quotaScope: 'request'`） | 429 | 逐字採下方 A6 request 日／週列 | 減少支援的輸入量／使用其他較低成本功能 | 僅該功能區塊顯示；**地圖與其他較低成本功能維持可用**；不保證減量一定成功，不自動重試 |
| 短時請求過多 | 429 | 短時間內請求太多，請稍後再試。 | 稍後重試 | 僅在伺服器提供可靠 `Retry-After` 時顯示約略等待時間 |
| 相同識別碼的重複操作 | 409 `DUPLICATE_REQUEST` | 此操作已送出，請查看目前狀態。 | 僅顯示提示文字；不得提供查詢動作 | 不表示操作成功；不得自動重送或重新取得上游執行權；狀態查詢方式待契約另定 |
| 識別碼與原請求內容不一致 | 409 `IDEMPOTENCY_CONFLICT` | 操作識別碼與原請求不一致，請重新確認操作。 | 重新確認操作 | 不得沿用識別碼重送，不得自動重試 |
| 防護服務／成本模型故障 | 503 `PROTECTION_SERVICE_UNAVAILABLE` | 保護服務暫時無法確認使用狀態，付費功能先暫停。請稍後再試。 | 稍後由使用者重新操作／查看公開內容 | 不顯示價表版本、內部設定、封鎖原因或額度文案；不自動重送 |
| 額度狀態無法查詢或資料過期 | 不一定為 API 錯誤 | 目前無法確認額度狀態，付費功能先暫停。你仍可查看公開內容。 | 重新整理狀態／查看公開內容 | 不顯示舊剩餘金額；付費 API 後端仍 fail-closed |

不得用「當期額度已用盡」或「全站曫停」合併日／週額度的文案。2026-09-25 起，週額度狀態不得假裝追加金額有固定上限；若需顯示累計追加金額，必須標示為「已經發生之累計實際金額」而非「上限」。

重複／衝突的錯誤只能在後端已驗證目前 Session 與有效資格後呈現；已撤銷者必須先得到 403，不可看到原預留資訊。「查看目前狀態」只是非成功承諾的提示文字，查詢動作及所需 API 仍待後續契約定義。

## 登入、PWA 與可及性

2026-10-08 管理確認本機補足：鍵盤開啟將焦點移至有名稱的非 modal 確認區，正常 Tab 可到確認與取消；送出前取消返回原按鈕，成功刷新後移到詳情確認按鈕。未知結果使用 alert，保留相同操作鍵並停用取消換鍵，只提供手動同鍵確認；後續撤權拒絕不抹除先前未知。首次明確拒絕仍可取消修正；處理中使用 status。離頁只取消 client 等待，不表示後端回滾或新增持久儲存。

- 登入 callback 成功後，只回到安全的 app 內位置；不得自動補送付費請求。無效返回位置回首頁。
- 登出後下一次付費請求依後端最新 Session 狀態處理；公開內容與既有本機公開快取不因此被描述為可收回。
- `/api/` 回應與憑證不得進 PWA 快取。舊分頁或離線 App Shell 不得繞過後端資格或額度檢查。
- 錯誤使用 `role="alert"` 或等效 assertive 語意，處理中使用 `role="status"` 或等效 polite 語意；登入、登出、重試、返回等操作均可鍵盤觸及。

## 實作階段驗收（目前均為待測）

- 在隔離瀏覽器環境以 Network／HAR 或等效可稽核證據，逐一驗證 Public、未登入、已登入未核准、已撤銷、已到期、當日額度已滿、每週額度已滿：圖磚代理請求數為 **0**，`/api/places` 呼叫數為 **0**；亦可直接對 `/api/map/tile/*` 發出請求，確認以上身分皆被拒絕且無對應 Geoapify 上游呼叫。
- 撤銷情境須額外驗證：地圖已開啟且已載入部分圖磚時撤銷資格，同一分頁下一次平移／縮放觸發的圖磚請求必須被代理拒絕；報告須明確排除「撤銷前已完成的請求」與「裝置上已呈現圖磚影像」兩類不宣稱可追回的情形。
- 每一受限狀態都要覆蓋初次進入、重新整理、舊分頁恢復，以及模式、資格或額度變更後的行為；確認前端沒有背景預取、自動重試；舊分頁殘留請求不由前端保證為零，抵達代理後須逐請求 401／403／429 拒絕且上游零呼叫（口徑見 spec FR-044）。
- 驗收必須觀察實際網路請求；CSS 隱藏、DOM 不可見、mock Leaflet 單元測試或僅檢查畫面截圖均不足以證明零圖磚請求。
- 以有效核准且日／週額度可用的第一級與第二級帳號驗證既有互動地圖、明確搜尋、結果 marker／卡片選取與導航交接沒有回歸；同時確認 `/api/places` 仍受後端授權與額度控制。
- 本次僅完成文件同步，以上應用程式與網路測試均未執行，不得標示 PASS。
